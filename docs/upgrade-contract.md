# Scope Recall 旧数据迁移契约

状态：实施决策与待验收要求，不是已发布能力。2026-09-06 用户确认新插件将接替旧 Hermes 版本，并继续扩展其他宿主。随后用户明确收窄要求：取消老用户自动升级兼容工程，交付便于操作的数据迁移工具和中文说明。本文件按最新要求细化 P14/P15/P16，不扩展冻结功能范围。

## 当前证据

- GitHub REST API 于 2026-09-06 实查：最新公开 Release 为 `v2.0.1`；`main` 为 `578b955802df753f2e2208e26eab6f71971285a0`，已包含后续合并。迁移支持以实际提交、schema 和配置识别，不能把推测的 `v2.0.3` 当作输入格式。
- 旧 SQLite 使用 `memories`、`journal_entries`、`fact_claims`、`fact_claim_evidence`、`task_episodes` 等表。新 Core schema 1105 使用 `source_events`、`claims`、`claim_versions`、`evidence_links`、统一删除记录等；相同数据库引擎不代表可以原样打开。
- 旧 Lance 行有文本和旧 scope 标识；新 Lance 元数据绑定安装身份、对象版本及 embedding space，正文从 SQLite 取回。即便物理表列可承载新元数据，旧行也不自动满足新读取契约。
- 当前迁移器已实现隔离备份、来源导入、事实与经验版本映射、删除阻断和 Core restore fence。V8 的公开合成数据验证已通过当前／历史、更正及删除后重复迁移检查；仍需与最终安装包和项目验收一并收口，不能宣称已经发布或支持原地自动升级。

## 用户操作范围

交付一次性离线迁移命令和简明中文说明：停止旧插件写入、备份原库、先按正常宿主 installer 建立空实例及官方 installation manifest、用 manifest-aware migrate 将旧 scope 显式映射到已绑定 audience、阅读报告并核对记忆、按宿主说明启用新插件。迁移从 manifest 推导目标目录、agent identity 和 installation identity，用户不再手填这些身份值；通常提供旧 scope 到 audience 名的映射；已确认旧库只有一个 scope 时，也可使用 `--single-scope-to AUDIENCE`，工具会自行确认唯一 scope。多个 scope 使用该简化选项时必须明确阻断，不得 SQL 改元数据、隐式扩大 scope 或静默丢失。跨实例、未映射或多个旧 scope 合并到同一 audience 时必须阻断。重复导入不得产生重复数据。迁移不提供自动升级和常驻兼容层。

不实现旧 `update` 命令到新发行格式的自动衔接，不维护旧 API、不接管正式 gateway 的自动停止/重启，也不承诺旧用户原地更新后无感切换。manifest-aware handoff 是一次性迁移入口，不是长期兼容层。原自动升级方案已被本次收窄替代。

说明应包含输入输出、备份位置、失败处理及向量索引状态；迁移不触发历史记忆的模型重总结，不默认发起付费 embedding 或记忆外发。索引未就绪时显示可用能力，不把语义检索已就绪写成成功条件之外的隐含承诺。

交付迁移说明以前，必须在隔离环境用真实旧版初始化的数据库验证其中命令。当前项目只演练，不改五个正式实例，也不发布升级。

## 数据去向

| 数据 | 转换要求 |
| --- | --- |
| 原始对话、工具结果、记忆正文 | 保留可归因来源、稳定映射、时间精度与原始来源身份；凭据不进入普通导出。旧库受保护备份保留原貌。 |
| 已确认事实与纠正历史 | 映射到自然 claim slot，保留当前、被替代、撤回、争议及证据关系；旧 fact key、fingerprint 等元数据留在已清洗的 source archive，并通过 evidence link 关联 claim revision，不写入非法 authority payload 条件。无法无损表达的历史只进入 archive-only 并阻断切换。 |
| 未确认候选 | 保留候选状态和可检查来源；迁移本身不批准或晋升。 |
| 经验与操作方法 | 把有依据的 procedure 和结果证据迁入同一权威；历史快照和旧标识留在 archive 并建立关联；不保留旧反思或 Playbook 引擎作为常驻依赖。 |
| 删除与抑制 | 先应用状态与依赖闭包，再允许读取和建索引。旧删除内容不能因导入、恢复或重建索引重新可见。 |
| scope、项目和权限 | 依据旧版真实私有与共享语义精确转换，不能把未知值改成宽泛权限；不可表达的权限阻断切换并保留旧安装。 |
| 附件和精确引用 | 保留来源绑定、引用及保留状态；缺失文件报告缺失，不伪造附件，也不移动宿主原始会话。 |
| FTS 与向量索引 | 作为可重建派生数据处理，不能以行数相等证明记忆等价。 |

## 向量复用与升级耗时

只有实际 embedding 模型/版本、维度、输入编码、分段、文本哈希和来源映射等均能验证时，才复用旧向量并转换元数据。不兼容或来历不明的向量保留在旧快照中；新实例先用通过验收的词法读取，索引作为明确可见、可恢复的后台工作。

数据复制和结构转换不需要让模型重新阅读全部历史。重新生成 embedding 是否需要外部服务及费用，取决于用户已授权路由和策略；不能把安装升级隐式等同于外发批准。升级时间须用实际数据量测量，不承诺固定秒数。

## 兼容代码边界

旧格式读取位于一次性维护工具，可独立交付并限定支持的旧格式。日常 capture、claim 更新、recall 和后台队列只调用新 Core。不得长期双写旧库与新库，不得在 recall 内遇到旧数据再调用旧 Provider，也不增加常驻旧格式兼容层。未来增加宿主优先增加 adapter，数据格式按独立 schema 版本迁移。

删除旧实现之前，要证明上述数据映射及独立迁移命令已可用。不能为减少代码提前丢弃迁移所需逻辑，也不能为迁移把全部旧引擎打进新运行包。旧动作回执和已退出治理引擎的日志作为历史记录保存，不新增当前权威或维持旧命令重放 API。

## 失败恢复与验收

1. 迁移失败或报告为 `blocked`：保留旧库和完整备份，禁止部分新数据覆盖原库。报告新库是否为未完成状态；archive-only 记录不等于可检索记忆迁移完成，未完成库不得被安装器当作已经迁移完毕。
2. 切换后新增的来源和删除记录必须保存。旧格式不能无损表达时，保留新库并停止危险写入，不直接覆盖旧快照冒充无损回退。
3. 使用公开 v2.0.1 和冻结 main 的真实初始化路径建立测试数据库，涵盖已确认事实、更正、候选、procedure、私有 scope、删除与附件引用。自编最小 schema 只能作为单元测试。
4. 迁移前后比较记忆状态、证据展开、当前/历史答案、候选可见性、删除负例和隔离负例，并验证重复执行、断电中断及失败恢复。全部主张降为 sources 或全部未知表列为 unmapped 不满足完整升级验收。
5. 公开支持列表只包含实际通过上述验证的旧格式。未知扩展、无法保留的权限和未覆盖后端应保持原安装并给出具体原因，不能自动清空、猜测或放宽访问。

以上验收未通过前，当前 `3.0.0.dev0` 仅为本地开发候选。
