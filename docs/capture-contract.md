# 来源捕获：已实施边界

P04 在同一 SQLite 事务提交来源、中文二元词/完整标识词法投影、唯一 consolidate/embed 工作项。辅助模型可以完全停用；原文检索不依赖它们。来源不是 active Claim，capture 回执的 mutation 固定为 none。候选与正式主张的碰撞/晋升规则继续由 P05/P10 的同一主张存储实现。

复用 secret_patterns 的统一 Unicode/凭据扫描和 capture_filters 的二进制传输识别，新增只去除传输载荷的原文过滤函数。秘密在生成来源指纹、写库、建立词项或工作前拒绝。原始段落的缩进、换行、标点和限定词保持；被去掉的 base64/附件缓存标记导致 partial 与 capture_gaps。不会用带脱敏占位符的内容声称完整原文已保存。现有“好/收到”等 trivial 过滤不适用于来源发生记录，因为 C14 要保留真实重复发言。

协议入站总量由既有 2 MiB 边界限制，超长正文按至多 65,536 字符稳定分段，每个字符恰好保留一次；组键来自宿主发生键，不能由正文哈希生成。宿主已经分段的材料保留其组、序号、总数与截断信息，过大的嵌套段拒绝，不伪造两个层次的序号。保存一批自动分段是一个原子事务；宿主逐段送达时，缺段可见为 source_segments_incomplete。修订变短不会把旧版多余尾段当作当前来源返回。

同键同版本重放不改变首次记录时间、epoch、词法或工作状态。回执读取实际投影状态；已有来源却没有索引时，不返回 ready，也不在重放或查询时暗中修复。内容、origin、发生时间或可信范围冲突返回 conflict。history 可以展开旧来源；普通原文检索只返回来源组的最新修订。原文检索结果仍不是“当前真实事实”。

P04 的 M01–M05 证据仅覆盖原文、限定词、角色/来源和精确版本读取，未冒称模型已经正确理解假设、引用或提议。C01/C02/C03 同样只证明失败/取消/原因可跨会话查回。C13 当前证明来源类型不被 user 角色覆盖、文本不被执行；独立证据根去重在 P05 的 evidence_links 实施，完整语义质量继续在后续真实提取和留出测试验证。

实际进程测试在写事务前、来源写后、词法写后、commit 前、commit 后回执前调用 os._exit。子进程没有执行 Python 清理；另一个进程重开数据库并重放同一来源。五个场景均保持一条逻辑来源、两个唯一工作项及正确原文。45 条断言是五个进程场景的检查，不是 45 次宿主或模型测试。首轮错误的测试函数参数顺序及后续修复结果一并保存。

schema 从 P03 的 1100 提升为 1101。新目标初始化会创建完整新结构，普通运行拒绝旧/未知版本；已有隔离目标的显式迁移在 P14 实施。没有改动活动库。
