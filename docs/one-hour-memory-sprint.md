# 一小时记忆改进冲刺：3.1.0.dev3

基线：冻结的 `3.1.0.dev2`，提交 `ac053c28f53d74fb584bbf9a39103e84d0182824`。
本轮仅在独立分支 `codex/one-hour-memory-20260912` 实施；没有替换天枢或其他生产实例。

这是按一小时时限交付的关键改进候选。下列已实现能力与剩余限制是不同的验收范围；此前 dev2 的测试成绩不自动算作本版本的成绩。

## 已实现

### 接收失败如实显示，重试重新核对授权

- 待处理计数使用观察账本与真实内存重试缓冲区的并集，写入失败不会再因为账本回滚而假报零待处理。
- 重试前重新读取安装授权，取原事件授权、原会话受众的现行授权及当前受众授权的交集；撤销的授权不能继续写入。
- 重放保留原始事件 ID、会话、角色和时间；明确标记尚未落库内容只是 `memory_only`。这不等于完成了跨进程持久接收。

### 长内容可以持续加工

- 对已经保存在 SQLite 的长来源按真实请求预算切成连续片段，保留原始来源 ID、版本与引文，不创建第二份原文存储。
- 每次工作租约至多一次模型请求。原文片段、系统规则及 schema 的请求总长仍不超过 16,000 UTF-8 字节。
- 已接受事实与片段进度在同一事务提交。未到原文结尾时工作保持 pending，进程重启后从持久进度继续。
- 片段不能声称已经生成整条来源的任务摘要或附件指代结果；这些输出会被拒绝。资格检查仍依据完整原始来源，保留被截在片段外的否定和限定信息。
- 旧版已因输入超长而失败的工作，只有实际重现输入预算错误后才获得一次精准修复；保留旧失败次数与修复标记，其他模型无效结果不获得无限重试。

### 没有新聊天时，后台仍可继续

- 现有 worker 外增加有限 supervisor，按持久工作队列的待处理时间、租约过期、失败冷却和预算窗口继续推进。
- 默认启用，每个精确授权范围最多持续 6 小时、256 次 drain；最长允许配置 24 小时、1024 次。现有单轮、每日任务和模型费用上限继续生效。
- 同一范围的启动请求合并，真实写入仍使用现有实例锁；不递归创建 supervisor。
- 空队列退出；终态失败显示 blocked；到达持续时间或次数上限显示 suspended。可恢复的能力问题退避，不能阻塞其他可用工作类别。
- 关闭宿主后可以继续处理未来到期工作。操作系统重启后的自动注册与启动不在本轮范围。

### 条件、更正与身份更谨慎且更易匹配

- 条件支持 `当 X 时`、`X 时`、`when X` 等语法外壳和空白规范化，仍需明确的正向条件依据。
- 普通提问不再一律否定已经明确给出的任务条件；直接询问条件真假、否定、假设和转述保持保守处理。
- 防止把“我朋友／我同事”的偏好当成用户偏好，保留忠实的负向自述；修复英文句末标点妨碍完整字面证据匹配的问题。
- 明确更正允许受限的省略谓词，但继续检查否定、时间和条件，不能跳过资格检查。
- 临时要求或临时撤回不能悄悄覆盖长期规则；明确替换需要绑定旧值和原始陈述。

### 画像与召回优先提供有用内容

- 在原有 24 个背景候选限额内，给查询相关偏好和稳定全局偏好保留候选位置，减少近期项目内容挤掉旧偏好的情况。
- 同一属性只有一个明确匹配例外时，使用该例外；多个同时匹配的不同条件给出相反值时，不按时间或分数任选一个。
- 已通过范围、时间、来源检查的检索候选，再按问题覆盖和重复证据进行轻量排序；不调用额外重排模型。历史查询保留原排序。
- 大条目放不进预算时，继续考察后面的较小候选；最终输出仍经过原有字节预算与删除状态复核。

## 数据版本与运行设置

本版本数据库结构为 **1106**，增加一个不含正文的 `work_items.consolidation_offset` 数字字段。

已有 1105 数据库必须先保留一致性备份、停止旧版本写入，再由新版本的显式 `MemoryCore.initialize()` 路径完成升级。升级前检查数据库应用标识、实例身份和原结构版本，在一个事务内增加字段。普通读取和 worker 启动不会偷偷迁移数据库。

升级后旧 dev2 无法直接读取 1106 数据库。恢复旧版本必须使用匹配的备份或另行验证的兼容回退，不能直接混用两个版本写同一数据库。本轮没有对生产执行升级。

新增可选 runtime 设置：

```json
{
  "supervisor_enabled": true,
  "supervisor_seconds": 21600,
  "supervisor_max_drains": 256
}
```

这些选项控制既有受信实例配置，不创建新的权限、凭据或费用额度。处于 basic 模式、未配置对应模型能力时，不会凭空获得提炼和向量能力。

## 必须保留的边界

1. **完整持久接收与重启重放尚未完成。** Core 已确认写入的事件持久化；发生写入失败且仅留在 Hermes 内存重试缓冲区的 DTO，宿主崩溃后仍可能丢失。单独写一个原文 sidecar 会绕过当前删除、物理清理和恢复闭包，因此本轮没有用这种方式假装补齐。后续需由 Core 管理接收队列生命周期，或由 Hermes 提供可信原事件回读接口。
2. **有界持续运行不等于永久服务。** supervisor 到时退出、机器重启后需要新的合法启动入口。预算不足不保证任意吞吐量下永不积压。
3. **长来源事实加工不等于跨片完整理解。** 本轮不生成跨片任务摘要和指代关系；无句界超长文本可能跨片拆开关系，完整证据检查可以阻止部分错误，但不能保证没有漏提炼。
4. **条件改进不是通用语义引擎。** 未引入通用人物消歧、任意同义属性合并或自主推理；相对“今天／本次”的条件在缺少充分时间和范围证明时，不自动作为长期背景启用。
5. **没有独立真实模型准确率或跨周使用结论。** 本轮使用语法检查、必要的定向离线反例和隔离子进程验证。没有全量测试、付费模型评测或生产探针。

## 用户侧验收重点

- 长来源在中断后继续加工，不能只保存原文就显示处理完成。
- 不再发消息时，已有到期工作仍在有限运行窗口内自动推进。
- 明确更正不能把“不用某值”截成“使用某值”；一次临时要求不会永久替代长期规则。
- 旧偏好可以被问题找回，重复内容不挤占全部上下文，冲突条件不被任意裁决。

具体检查结果、构建产物哈希与源文件清单随交付包保存。
