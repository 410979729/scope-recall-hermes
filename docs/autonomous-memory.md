# 无人值守记忆：3.1.0.dev2

本候选从阿戊最新的 3.0 修复包 `68bd9c70807b8364a2d99b755e29a83437ecf23020b82c01aaf3d42e0732c2a5` 派生。源码独立复制，原包和原源码压缩备份保留；本轮不替换生产实例、不迁移旧数据库、不公开发布。`autonomous-memory-acceptance.md` 记录本轮验收范围。

## 日常如何工作

1. Hermes 捕获用户输入和工具观察，原文、来源身份、时间、词法索引在同一事务中保存。明确的偏好、决定、更正和未知实质内容继续进入加工队列；纯“收到”、空成功回执等只保留来源，不再制造长期待办。它们仍可被词法检索，也仍参与会话来源关联。
2. 主机捕获成功、压缩前和会话结束会唤醒合并后的短时 worker。worker 有次数、时间、队列和辅助模型预算上限。缺少模型或向量能力时，对应队列等待能力恢复，不消耗失败次数。没有启动常驻服务。
3. 自动召回将当前问题证据与最多两条有效偏好/约束、一个有可靠来源的当前任务共同装入有界上下文。所有背景内容仍保留主语、来源与适用条件；无关背景不会让“没有答案”变成“有证据支持”。模型显式调用 `recall` 工具（Hermes 工具与 Codex MCP）而查询本身没有找到证据时，不附带偏好/约束背景，结果为 `no_match`；只有查询含“继续”等恢复词且存在唯一有来源的当前任务时，仍附带该任务。显式历史查询不会混入当前任务。
4. “继续任务”在普通召回缺少任务时最多补查一次。多个任务无法确定唯一目标时保留歧义，不靠最近时间擅自选一个。原有关系检索仍限制两跳、最多 24 个对象。
5. 明确的“换成”“调整为”“停止使用”等可以直接更正或撤回唯一目标，原版本与原文保留。目标查找先按相关内容过滤，修复超过 200 条记忆时漏掉目标的问题。引用、否定、疑问、条件、已识别的未来表达不会走立即修改通道；自然语言不明确时仅保存原文，不猜测授权。

本轮没有引入需要人工清理的 Journal。`source_only` 是正常处理结果；`deferred` 表示容量不足、以后有限补入。两者存储在内部调度元数据中，不会被当成缺失证据，不会发送给提炼模型。

工具输出有两种情况在捕获时直接按 `source_only` 处理：与本 scope 内更早一条工具输出内容完全相同的重复（`tool_output_repeat`），以及捕获过滤器为被省略的输出留下的占位摘要（`tool_output_omitted`）。两者原文与词法索引照常保留，只是不再嵌入、不再进入整理。在一台实例上，16.8 万条来源里有 13.2 万条是这两类。

自 3.2.0 起，其余工具输出也不再进入整理：原文、词法索引和向量照常保留，按字、按意思都能查到，但不再从中提炼记忆事实（`DERIVATION_ROOT_ORIGINS` 里没有工具输出，接收时只排向量任务）。agent 读过、运行过的内容不是它该记住的东西；怎么做一类任务，由主机提炼成技能。试点库上，一个 2.5 小时的任务从工具输出里提炼出 787 条事实（文件大小、路径、端口、创建时间），全库 93% 的事实只来自工具输出，而主人的 30 个真实问题没有一个靠它们回答。更早版本提炼出、还没确认的这类事实，用 `retire-rootless-claims` 撤下（见 `install.md`）。

## 默认边界

| 项目 | 默认值与行为 |
| --- | --- |
| 加工队列容量 | 每 scope/project/branch 的 pending+leased 普通总上限 2048，重要内容总预留 128，均分给 consolidate、embed 两个独立队列；允许先排一类，另一类延期，缺失的可选向量能力不会阻塞记忆提炼 |
| 延后补入 | 每次 drain 前至多检查 16 个 deferred 来源，仍检查容量、来源当前版本与权限；两小时内持久化的用户输入与工具观察先补入，并可使用重要内容预留，但不会因此被记为重要内容 |
| 低价值来源 | 不生成昂贵工作；可信调用方可用 `MemoryCore.schedule_source` 按需加工，不重置已有失败任务 |
| worker 单次 | 最多 32 项，最长 120 秒；模型请求最长 45 秒 |
| 新鲜对话优先 | 每次 drain 的第 2、4、6… 次领取优先选择两小时内持久化的用户输入（提炼、向量）、工具观察与助手可见回复（仅向量），其中按可用时间先后；删除清理始终最先，其余领取保持 FIFO，积压每次 drain 至少占一半领取。该通道只检查最近可用的 512 项，超出部分仍按 FIFO 处理 |
| 唤醒间隔 | 默认 30 秒；在固定 project/branch 内按完全相同的授权 scope 集合合并，最多 8 组，每组一个执行进程和一个尾随进程；超过容量明确报告缺口，不合并权限。共享 writer 仍串行，等待前驱、锁等待与执行共用原有期限 |
| 当日加工上限 | 默认 256 项；达到后仍优先执行删除清理 |
| 临时失败 | 原三次尝试后，冷却一小时，最多自动恢复两次；累计 attempt 不清零 |
| 永久错误 | 权限、推导不合法等不自动复活；来源被删除、撤权或替代的工作作废 |
| 模型费用 | 独立辅助模型账本限制调用数、输入输出、费用；自动恢复不扩张、不重置预算；预算拒绝暂停加工 |
| 自动背景 | 最多两条偏好/约束与一个任务；候选扫描上限 24，偏好文本每条最多 768 UTF-8 字节；共享最终 packet 上限 |
| 召回预算 | 现有 `budget_tokens` 字段实际按保守 UTF-8 字节单位计；装不下最小有效信封时明确拒绝，不返回超限数据 |

`runtime-config.json` 的可信配置可覆盖 `daily_work_limit`（0–1000000，**0 表示不限**，默认即 0）、`auto_retry_cooldown_seconds`（60–86400）、`max_auto_recoveries`（0–4）、`worker_min_interval_seconds`（1–3600），原 `max_items`、`request_seconds`、`drain_seconds` 仍有效。修改后下一次进程加载生效。上限是保护措施，不意味着推荐把它们调到最大。

`daily_work_limit` 不是花费闸门：金额、调用数与 token 由辅助模型账本（`runtime/model_budget.py`）在每次请求前于 `BEGIN IMMEDIATE` 事务中按五道独立上限强制执行。该计数只限制每天尝试多少个队列项，且看不到任何一项的成本。把它设成低于实际产生速率的值，结果不是省钱而是永久积压：实测一台轻度使用的实例，一天 127 条原生来源产生 1,913 个工作项，旧默认值 256 只能处理其中 13%，积压每天净增约 1,650 且永不追平。

辅助模型必须显式配置并有预算账本。模型不可用时，原文与词法召回仍正常，提炼的偏好/任务不会凭空生成。Core 嵌入方可通过 `CoreConfig.admission_policy` 设置 `AdmissionPolicy`；运行时默认使用上表值。主机配置不是用户聊天或模型工具参数，不能用聊天文本修改身份、范围或预算。

OpenCode Go 的提炼路由允许显式设置 `consolidation.reasoning_effort: "none"`，以及 `response_format: {"type": "json_object"}`。其他路由保持原来的推理参数校验。不同服务的关闭推理参数有差异，参见 [OpenCode 上游问题记录](https://github.com/anomalyco/opencode/issues/46178)；本轮保留了原超时记录，实际结果以交付的原生验收回执为准。

## 生命周期与故障

有效时间、已撤回/被替代版本、删除/抑制、来源版本和权限都由原 SQLite 事实层判定，背景召回复用相同的读取与最终释放检查。过期内容不进入当前背景；没有有效截止时间的事实不会仅因变旧而自动删除。自动“遗忘”体现为当前视图排除失效内容，不会擅自擦除审计来源。显式删除仍按原授权流程立即阻断读取并优先清理派生数据。

同一 Hermes 进程里，压缩前与结束时只重试已经观察过且捕获失败的原始 DTO；不会把无来源 ID 的摘要冒充用户原文，也不宣称能恢复进程崩溃前从未捕获的消息。长时停机、缺少凭据和耗尽预算需要环境恢复，插件不会无限调用模型来“自愈”。后台恢复由后续主机活动触发，空闲期间没有额外常驻计时任务。

`doctor` 显示 pending/leased/failed、最老待办、最近工作器结果和最近成功时间，并汇总当前可见且未抑制的 `source_only_sources`、`deferred_sources` 和最早延后来源时间。计数单位为当前来源分段；长消息可对应多个分段。待办年龄使用最初持久化时间，不因重试时间后移而清零。`--python` 会报告目标解释器实际加载的包版本、位置和版本不匹配，不能把“可以 import”当成新候选已经装好。`runtime-worker-status.json` 只存有限状态元数据，异常回执不包含模型文本或凭据。状态显示成功不等同于每条事实语义正确。条件适用目前采用字面匹配，复杂条件、多人物关系和任意自然语言更正仍有保守拒绝边界。

## 安装与回退

使用本轮实际交付的 wheel，按 `install.md` 在独立环境安装。源码、wheel、隔离安装目录必须逐文件相符。私有候选版本为 `3.1.0.dev2`；插件清单采用等价的 SemVer 表示。本任务未修改生产安装，真实实例部署由单独的部署任务验证。

若以后部署本候选，部署前先备份对应实例数据及配置。正常卸载默认保留 Core 数据；不要把 purge 当作回退操作。旧版本重新安装也应使用备份的环境与数据库，不能把本轮隔离验证解释为对所有旧版数据库的迁移保证。
