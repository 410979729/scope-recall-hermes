# 情景、恢复状态与产物版本

本文件说明情景、恢复状态与产物的写入和读取边界。

`MemoryCore`（`core/composition.py`）提供 `episodes`，`MemoryCore.records` 提供 `episode_sources`、`accept_consolidation`、`register_artifact`、`artifact`、`open_artifact` 和 `reference`，`MemoryCore.operations` 提供 `purge_attachments`，都在存储的同一 SQLite 事务边界内。导入这些模块不会触发旧库迁移或维护命令。

## 情景和恢复状态

可靠 task anchor 与 scope/project/branch 共同确定情景身份；跨会话仍可接续。没有 task anchor 时，只有实际观察到的同一产物版本能够连接唯一已有情景，否则采用同会话的 provisional 区间。明确换题开始新情景，相同标题不合并不同项目或无锚点的新会话。

每段最多保存 200 个事件的归属与摘要依赖，超过后建立同 series 的下一段。读取原始来源支持有限分页，摘要记录 `processed_sequence`、来源版本和 watermark，新增或修订来源会标明未处理尾部或需要重建；旧摘要不能作为最新自动交付结果。

状态区分 open/completed/failed/cancelled/interrupted/unknown。助手承诺不构成完成；普通闲聊不制造目标；暂停不等于取消；时间按规范化 UTC 排序，迟到的旧失败不覆盖已有的较新完成记录。规则是保守的确定性资格检查，不能单凭这些正则宣称已经理解所有自然语言。

恢复摘要必须逐字引用有效来源。目标与决定需要原始人类来源；验证进展需要完整的人类确认或实际工具观察，拒绝假设、否定、问题和助手承诺的错误晋升。受控导入的人类身份只在已批准 TEST 导入清单的精确指纹匹配后生效。模型不会获得可信 context 的构造权限。

验证进展依赖来源当时的 environment revision。新工作区中添加一个事件，或重新提交旧进展的摘要，均不能把旧环境验证变成新验证。读取会标记 `needs_revalidation`。

引文所在子句的否定和限制必须完整保留：把“没有确认”截成“确认”、把“不要执行”截成已授权的下一步都会被拒绝，疑问也不能充当目标、决定或已授权的下一步。完整的负面决定仍可保存，独立的肯定子句仍可执行。同一来源资格检查也覆盖无问号的中文问句、捕获时的更正快路径、删除授权和否定的取消语句。

## 产物和指代

产物使用稳定 ID 与整数版本，名称和路径不承担身份。注册需要已捕获的产物来源和运行时授权的绝对路径、媒体类型、大小上限、预期 SHA-256。只保留获准文件，内容以哈希寻址写入实例自身的 retained 目录。同路径被覆盖后，旧版本仍能按原字节打开。

读取再次核对 installation/agent、作用域、来源、删除状态、大小和哈希，返回 `(Artifact, bytes)`。只存描述或原文件缺失时返回明确缺口；不会根据描述生成图片冒充原件。

Windows 长路径只在文件 I/O 层转成扩展路径，权限判断保留规范化逻辑路径；符号链接和 junction 祖先被拒绝。删除只处理归属本次 tombstone 的附件，仍有合法引用的共享 blob 保留。事务失败可能留下未引用的 CAS 文件；在线可见性仍立即关闭。

指代候选只能指向可访问、真实出现的产物版本。展示序号必须来自实际 observed snapshot；第 0 张无效。工具和助手不能代替用户消歧。同名身份冲突不能靠模型少报候选变成唯一；版本号必须与所指名称相连。后续明确澄清创建新的 binding revision，保留历史并使旧派生恢复状态失效。恢复状态的产物引用必须有精确版本的展示证据或该版本的注册来源；仅仅见过稳定产物 ID 或旧版，不能替另一个版本提供证据。

项目改名复用 Claim：已有、同范围且当前有效的命名事实提供稳定目标，独立 alias Claim 保存有来源的新称和目标引用，原命名事实及旧称保留。人类原文必须明确把目标的名称或稳定 subject 改为完整新称；普通提及新名、同范围无关事实、其他项目、问句和假设均不能建立关系。产物名称关系使用版本化 ReferenceBinding，不另建项目真值表。

## 模型输入

`core/consolidate.py:consolidation_messages` 是可复用的纯输入格式器：最多 32 条已授权原始来源、最多 16000 UTF-8 字节，附真实 schema、角色、来源版本、水位和已观察到的产物版本。它不接收答案、后续查询或预置 Claim。传输与调度位于核心之外；接受提议时，在同一个写事务中重新校验全部来源、权限和依赖，任一错误回滚整个提议。
