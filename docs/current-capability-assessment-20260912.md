# 八项问题核对：以当前代码和阿甲实库为准

核对对象：dev6 运行代码及整合后的 3.1.0rc1 候选；生产阿甲仍为 dev6 / schema 1106。本文件是现状判断和后续清单，不是把八项自动全部加入本轮开发。未重新验证用户所述阿戊快照“48 个 scope”的统计。

| 项目 | 判断 | 准确现状与缺口 |
|---|---|---|
| 1. 多受众安装 | **CLI 缺口存在；不能说底层不支持** | `maintenance/install.py::_initialize_instance` 默认仍用 `platform=cli,user_id=local`。但 dev6 的 `adapters/hermes/audiences.py` 已支持多个精确受众、各自读写范围及只读受众。缺的是生成、预览、校验及迁移映射的一体化工具。只给 `--add-platform telegram` 不足以决定哪个用户/群可读哪些私有记忆。未映射 scope 的拒绝需要保留。 |
| 2. 备份/回退 CLI | **原缺口属实，本轮已补** | rc1 提供 `scope-recall backup`，生成一致性快照及清单；`scope-recall rollback` 默认只读预览，`--apply` 才执行安全回退。新库有新增内容或持久接收队列时先保护新数据，不盲目覆盖。 |
| 3. 迁移与向量衔接 | **产品流程缺口存在** | 迁移器不复制旧向量是合理边界，但缺少通用“迁移完成→选定空间→安排重建→进度与完成验收”的单一入口。正常新事件已有 embed 工作及后台处理。阿甲本轮只读看到 1,632 条 embed 工作为 done，不能仅根据迁移文档断言它现在完全没有语义检索；本次没有重新跑原生索引或真实模型质量验收。 |
| 4. 画像完全被动 | **说法不准确** | `core/background_context.py` 已在自动召回中按当前条件选少量有效事实，并可补一个明确的当前任务；不是必须调用 profile 才能使用画像事实。完整 profile/entity 仍是显式视图。自动画像的覆盖率、主体理解和质量仍应优化。 |
| 5. 整个插件只有一跳 | **部分属实** | `core/read_views.py::read_entity` 确实是一跳接口；主召回 `core/recall.py::_expand` 和 `core/retrieval.py` 已有最多两层的受限关系扩展。这不等于用户举例中的多实体、多条件关系查询规划器，后者尚缺。 |
| 6. 事实都必须人工批准 | **机制描述不准确，实际体验问题确实存在** | `core/claims.py::qualify` 能把充分支持的新提议直接判为 active；`core/mutate.py::apply_claim` 可用新增证据形成新版本。迁移报告中的 `candidate_auto_promoted=False` 指不能因导入而给旧候选凭空增加权威。已存 proposed 也不能仅因等待而变成事实，但其自动补证、失效及归档流程仍不完善。见下方实库观察。 |
| 7. budget_tokens 实为字节 | **属实，是接口语义问题** | `core/read_views.py::_budget_bytes` 和召回包限制使用 UTF-8 序列化字节数，不是真实 tokenizer。4096 还包含 JSON 元数据，不能理解成 4096 个模型 token。应把字节上限与 token 预算分开，并提供模型适配及明确的估算降级。 |
| 8. 企业与生态能力 | **必须拆开** | 当前 v3 没有 PostgreSQL/pgvector 分布式后端。平台字段、owner_principals 和精确受众并非固定平台白名单，可声明其他平台；但没有由此证明所有平台的实际宿主适配已验收。子代理已通过 `agent_context=subagent` 限制为只读；尚无临时授权、到期撤销和专用临时记忆区。 |

## 阿甲 proposed 的实际情况

本轮只读查询看到 **101 个事实版本，72 个当前事实头，全部为 proposed**。这是当前生产数据，不是合成测试结果。

- 42 个当前头来自旧候选或缺少同范围精确证据的历史迁移。
- 30 个当前头来自新提炼：12 个主体未绑定、12 个事实关系未被证据证明、5 个问句或未确认表达、1 个缺少人类授权来源。

抽样可见，部分提议把临时“帮我写宣传文案”请求生成了长期 intention，并凭空添加“用户/human_direct”等主体；另一些只分别引用文件名和哈希，没有给出两者关系的完整证据。不能把这些候选全部强行转为 active，也不能把“代码允许自动生效”当成真实体验已经达标。

后续主方向是自动提高抽取质量、遇到新证据再核验、合并重复候选、按明确条件失效或归档，并保留原文检索。**不以管理员逐条按 Y/N 作为正常使用前提。** 自动加工失败及 source_only/partial 必须可见，不能通过清空失败记录制造“无积压”。

## 后续优先级

先补受众与迁移/向量的一体化交付、实际提炼与候选自动生命周期、清楚的中文预算接口。再补更强的有据实体查询。分布式企业后端和临时子代理授权放在企业需求明确后设计；它们不应阻止当前个人与小团队版本交付。

本轮 rc1 已完成的恢复、长文汇总、持久错误和运维命令详见 `3.1.0rc1-closeout.md`。本清单中的未完成项不会被 rc1 的定向测试结果覆盖。
