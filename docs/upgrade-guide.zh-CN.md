# 让 Agent 安装或升级 Scope Recall

用户只需要说「帮我安装 Scope Recall」或「帮我升级一下 scoperecall」。
下面的流程由 Agent 执行，不要求用户操作命令行、填写权限映射或审阅记忆。

`scope-recall-setup` 技能会随安装器交付到 Hermes 和 Codex 的技能发现目录。
它只包含触发条件与分流入口；升级时才读取完整的
[Agent 操作流程](../maintenance/AGENT_WORKFLOW.md)，不把迁移规则塞进每轮提示词。
旧版本没有该技能时，Agent 从新版 README 获取入口，在隔离环境中读取新工具，
再操作旧实例。旧插件不会凭空获得新版技能。

## 三条路径

| 检测结果 | Agent 执行 | 用户体验 |
|---|---|---|
| 第一次安装，没有旧库 | 正常安装、绑定身份、配置所选模型、验证宿主 | 装好即可用，无迁移队列 |
| 已使用当前 Core | 备份、升级包和适配器、必要的 schema 升级、宿主检查 | 保留现有记忆和配置 |
| 使用旧版 SQLite | 固定快照与权限、迁移、核验、恢复检索、切换宿主 | 旧记忆继续可用，后台恢复向量索引 |

Agent 首先执行 `scope-recall setup --host <hermes-or-codex> --home <实际实例目录>`。
存在多个旧库、损坏、未知格式时，会明确返回待检查原因；不能当作新用户覆盖安装。

## 旧版迁移的执行边界

操作指引由 `scope-recall setup --workflow` 输出，并包含以下步骤：

1. 查明实际运行环境、数据路径、服务控制方式和旧版权限配置。
2. 在独立目标中准备安装清单。保留可验证的账户、私聊、群聊和项目权限。
   精确保留的 scope ID 自动映射；其余映射由 Agent 根据旧宿主记录生成。
3. 停止旧写入者，保存配置与附件，运行 `migrate prepare` 创建一致快照和持久任务。
4. 运行 `migrate run`，复用唯一的旧版转换器；中断后从任务继续，不重复重提炼旧 Journal。
5. 运行 `migrate verify` 核验报告、SQLite 完整性和数量；以 `migrate queue-index`
   分页恢复现有后台队列中的嵌入任务。排队完成不等于向量索引已完成。
6. 通过实际宿主控制器切换，并在实际 Agent 上验证旧记忆、纠正、删除和不同会话的访问范围。
7. 失败则恢复旧宿主；若新库已接收消息，先保留新增数据，再处理回滚。

源库变动、快照损坏、安装清单变更、权限缺失、未知转换语义都会阻止切换。
任务记录保留失败原因，最多允许三次转换尝试；不无限重试同一个问题。
所有这些检查和处理都由 Agent 完成，不创建人工记忆治理队列。

## 支持与验收

当前转换器支持已验证的官方 578b SQLite 基线及明确实现的兼容扩展。
阿甲 2.0.1 的特定读取语义需要 Agent 核对后显式选用对应契约。
旧向量目录不直接导入；SQLite 是真值，向量由现有 worker 重建。
未知表、未知列、无法无损表达的事实或权限仍需兼容工作，不能宣称任意旧版都完美迁移。

`3.1.0rc6` 是实现此入口的候选版本。离线迁移通过、wheel 安装成功、
实际宿主已加载、真实旧记忆可用分别记录；只完成前两项不能报告后两项成功。
发布或实例升级以对应构建的实际验收记录为准。
