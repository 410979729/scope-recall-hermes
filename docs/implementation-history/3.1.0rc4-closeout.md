# 3.1.0rc4 natural correction candidate

Natural corrections could leave an old preference active when extraction put
the same literal subject, verb and project in different fields. Background
processing order could also defeat a correction captured later.

The application and candidate paths now share evidence-bound grammatical
normalization for uniquely sourced, bracket-named projects. Modal verbs and
embedded preference frames become one slot; explicit applicability conditions
remain attached. This is a deliberately bounded grammar, not general semantic
entity resolution. Ambiguous subjects, other speakers, questions, unsupported
values and uncertain statements cannot be promoted by this repair.

Conflicting human assertions use their source time, or trusted live capture
order when both event times are unknown, without inventing historical dates.
Old evidence processed later cannot replace the current value. The model prompt
also asks for separate subject, predicate, value and applicability fields.

An upgrade can repair existing frames without a model or manual approval:

```
scope-recall repair-claim-frames --config ABSOLUTE_RUNTIME_CONFIG --limit 16
```

Continue with the returned `cursor` as `--after-ref` until `done` is true.
Each page revalidates evidence through normal claim application and reports
errors; it does not overwrite source text or historical version payloads.
Back up the instance first. The command returns nonzero on page errors.

Protocol 1.1 and schema 1108 are unchanged. No vector reimport or rebuild is
needed. Frozen failed model outputs cover delayed/reversed processing,
legacy repair, idempotence, candidate evaluation and public profile reads.
Candidate packaging and live Alpha receipts belong to the separate dated
acceptance directory. This patch does not certify all product release gates.
