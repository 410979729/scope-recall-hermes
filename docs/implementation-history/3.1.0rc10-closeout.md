# 3.1.0rc10 recall timeout repair

The reported calls exhausted their five-second recall deadline at the final
SQLite release fence and returned no items. Read-only profiling of the same
queries over the affected database found that five epoch checks ran full source
and work-queue statistics, consuming 1.7–2.6 seconds without vectors. The host's
delivery check performed another full diagnostic scan outside that deadline.

`Transaction.memory_epoch()` now reads the singleton metadata row in the existing
transaction. `MemoryCore.memory_epoch()` exposes a fresh, identity-checked read
to the two host recall dispatchers. `RetrievalStorage.epoch()` remains the
compiler's injectable fence boundary. No epoch is cached and no deletion,
permission, revision or release check was removed. Full statistics remain behind
the existing status operation.

`MemoryCore.recall_packet()` reserves 20% of the caller's original deadline,
capped at one second, for compilation and final release. Retrieval receives the
smaller budget; vectors retain their existing timeout allowance within it.
The total deadline and public request contract are unchanged.

The same reproduction found an oversized first hit consuming the preliminary
budget, excluding shorter hits and then being rejected by the compiler. Such
hits now follow usable evidence without consuming its budget; a standalone
oversized hit retains the existing expansion diagnostics. The compiler still
owns the final schema and complete packet byte limit.

Validation covered the existing packet deletion/epoch fences, three focused
regressions (no backlog diagnostics, oversized first hit, and a vector timeout
with slow fresh reads), and both host recall dispatchers. No full suite was run.
Two approved real Gemini Embedding 2 calls through the installed Hermes loader
completed in 3.53 and 3.28 seconds, each returning two items, with no timeout or
vector-service error. Coverage remained partial because of relation and packet
size limits; this does not certify every historical answer or a Telegram round
trip.

The adjacent P08 `test_P08_claim_state_reuses_current_history_and_as_of_semantics`
check failed at its `as_of` assertion both on the unchanged rc9 baseline and on
this candidate. It is recorded as an existing follow-up, not counted as a passing
check or silently fixed as part of this timeout patch.

Protocol 1.1 and SQLite schema 1108 are unchanged. No data conversion, queue
purge, re-embedding or configuration change is required. This local patch is not
a GitHub/PyPI release authorization.
