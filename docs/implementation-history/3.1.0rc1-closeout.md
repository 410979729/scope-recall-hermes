# Scope Recall 3.1.0rc1 收尾说明

本候选整合 dev6 wheel 的实际运行代码及阿甲迁移兼容代码，保留 3.x Git 分支、测试和构建清单。Python/Hermes 版本统一为 `3.1.0rc1`，Codex 清单采用等价的 `3.1.0-rc.1`；协议仍为 1.1，SQLite schema 升至 1107。

## 使用行为

- **接收恢复**：Hermes 先校验、过滤敏感内容，再写入 SQLite 接收队列，随后索引、安排加工。索引事务失败时返回 `queued`，跨进程保留原始事件、时间、用户身份和会话；完成写入与移除队列在同一事务内。重放重查当前宿主授权。SQLite 本身不可写时仍明确报未持久化，不能承诺磁盘故障时保存成功。
- **无人值守**：现有有限 supervisor 继续按到期时间、冷却和费用预算工作。可登记 Windows 登录触发及每五分钟检查的外部入口，覆盖程序退出、supervisor 达到上限和重新登录后的恢复；无到期任务时不启动模型。实际登记状态由 doctor 查询任务计划程序。配置和权限不匹配时停止，暂停后最多结束正在执行的单次调用，下一轮不再加工。
- **长文**：原文连续切片、逐片保存进度。先前片段的目标可作为有来源的上下文传给后续片段。只有完整连续覆盖后才发布汇总，继续校验原始全文中的否定、条件、来源和版本。多个目标、互相冲突的下一步或容量超限明确标记 `partial`；不会伪造“全部理解”。
- **提炼降级**：只接受完整 JSON 外壳、可省略的空类型附加字段以及能唯一对应存储原文的 JSON 转义修复。非空异类对象、模糊引文和无来源推断继续拒绝。三次提炼失败后保留原文检索，结束自动提炼任务并登记 `source_only`；保留失败记录，不冒充成功提炼，也不无限调用模型。
- **诊断**：记录失败阶段、错误码和有界字段名，不保存模型原始响应；doctor 单独展示持久接收积压、提炼降级、分片汇总缺口和最近失败。终态失败/降级显示 `attention`，注册、存储或可恢复故障显示 `degraded`。安装完成不再直接宣称完整宿主模式已验收。

接收队列限制为 256 条、共 64 MiB，单条校验后载荷最多 2 MiB。容量不足会明确拒收；后台每轮最多重放 8 条。敏感原文不会先写入另一份侧边日志。删除或抑制内容时，保守取消同一 scope/project/branch 的待接收事件，避免延迟事件抵消遗忘；这一操作可能同时取消该分区其他尚未正式接收的事件。

## Windows 恢复入口

在宿主使用的 Python 环境安装对应 wheel，完成身份核对、备份和显式 schema 初始化后使用：

```text
scope-recall autostart plan --config <绝对路径/runtime-config.json> --python <宿主Python绝对路径> --user-id <Windows用户或SID> --env-file <已有运行凭据环境文件>
scope-recall autostart enable --config <绝对路径/runtime-config.json> --python <宿主Python绝对路径> --user-id <Windows用户或SID> --env-file <已有运行凭据环境文件>
scope-recall autostart pause --config <绝对路径/runtime-config.json>
scope-recall autostart remove --config <绝对路径/runtime-config.json>
```

`--env-file` 可省略，届时沿用进程环境。指定时只读取配置明确引用的凭据键，不执行文件、不做变量插值，不把凭据写入任务 XML 或回执。此入口按配置中的 scope/project/branch 工作，不自行扩展到别的实例或分区。当前提供 Windows 用户登录后恢复；不声称机器尚未登录时或其他操作系统已经配置服务。`remove`/卸载会撤销本插件登记的任务。

## 升级、回退与验收范围

新增 `scope-recall backup --database <绝对数据库路径> --output <新备份路径>`，默认同时写入校验清单；不覆盖已有文件。

`scope-recall rollback --current-db <当前库> --snapshot <旧快照>` 默认只读预览，加 `--apply` 才执行底层安全回退流程。新库已有原始事件、删除操作或尚未加工的持久接收内容时，执行结果是保护新库、安装停写标记，等待数据协调；不会盲目覆盖生产库。

显式初始化支持 1105 → 1106 → 1107，同一事务先核验实例绑定。1106 的旧提炼失败先保存历史再获得一次新解码器机会；普通启动不会重复重置次数。旧分片缺少汇总证据，从原文开头重新建立连续覆盖，原始数据不改写。

1107 新增接收、分片汇总、加工结果和错误详情表。备份采用 SQLite 一致性备份。恢复旧快照时清空待接收队列并重建未完成分片汇总，删除台账继续生效。**回退 dev6 需要对应 1106 数据库备份，不能只降级 wheel**。不重建现有向量空间，不改 embedding 模型。

本轮定向验证覆盖故障恢复、权限、删除、分片、有限调度和宿主调用；具体结果在交付验收回执。合成测试、安装包检查和计划任务登记不能替代真实长期语义质量评价。既有 P08/G2 等未通过或未执行的验收不被本候选覆盖。商业稳定版发布、真实重启后的端到端验收及生产部署状态分别以对应证据为准。
